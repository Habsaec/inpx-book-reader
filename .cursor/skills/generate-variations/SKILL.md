# Generate Variations: Produce 3+ Design Options

Produce multiple distinct variations so the user can mix and match the strongest pieces.

## Cursor notes

- Present variations side-by-side in one file (tabs, toggle, or grid) — not v1/v2/v3 scattered files.
- Root variations in existing design system unless asked to break free.

## Phase 1: Establish baseline

Confirm: what is varied; existing context; count (default 3); axis preference (visuals, layout, interaction, copy).

## Phase 2: Pick axes

Vary 2–4 dimensions: visual treatment, layout, interaction model, hierarchy, tone, component style.

## Phase 3: Build basic to bold

1. **By the book** — matches existing patterns
2. **Refined** — same structure, 1–2 dimensions pushed
3. **Novel** — genuinely different take
4. **4–6** — hybrids or wildcards if requested

## Phase 4: Vary substantively

Differences in layout, hierarchy, density, interaction — not just button color. Specify each variation concretely before building.

## Phase 5: Single file presentation

Side-by-side grid, tabs, or tweak toggles. One file, all variations visible or switchable.

## Phase 6: Annotate and recommend

Caption each variation in 1–2 sentences. End with a clear recommendation — don't hedge that all are equally good.

Suggest next: refinement, `make-a-prototype`, or `polish-pass`.
